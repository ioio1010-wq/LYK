Segment Funnel, Insurance, Price Sensitivity Diagnostics

분석 대상은 identity_level != reservation_id인 canonical user와 해당 예약입니다. 비율 차이는 세그먼트 vs 나머지 전체의 two-proportion z-test로 계산하고 FDR 5% 기준을 표시했습니다. 가격민감도는 전역 가격 하위 25% 예약과 상위 25% 예약의 결제 완료율 차이로 봤습니다.

중요한 해석 주의사항. language=(unknown)은 성과가 좋은 언어가 아니라, 이벤트가 붙지 않은 예약 기반 customer 유저가 몰린 attribution 실패 그룹입니다. 또한 예약 row의 UTM은 대부분 (unknown)이라 source/medium/campaign 기준 가격민감도는 현재 데이터만으로 강하게 해석하지 않는 것이 안전합니다.

Analysis Steps

1. 데이터 정리

user_funnel_state.csv와 reservation_funnel_state.csv를 읽고, identity_level == reservation_id인 단위는 유저 분석에서 제외했습니다. 이 단위는 customer_id 없이 reservation_id만 있는 미식별 예약 단위라 유저 전환율을 과장할 수 있습니다.

2. 세그먼트 정의

유저 기준은 source, medium, campaign, language, channel = source / medium입니다. 결측이나 빈 문자열은 (unknown)으로 통일했습니다.

3. 유저 퍼널 계산

각 canonical user의 funnel_stage_rank가 특정 단계 rank 이상이면 그 단계에 도달한 것으로 봤습니다. 즉 단계별 수치는 순수 이벤트 카운트가 아니라 누적 도달 유저 수입니다.

4. 유의성 검정

각 세그먼트의 단계 도달률을 나머지 전체와 비교했습니다. 예를 들어 app 결제완료율은 app 유저와 non-app 유저의 결제완료율 차이를 two-proportion z-test로 계산하고, 여러 비교 문제는 Benjamini-Hochberg FDR로 보정했습니다.

5. 보험 선택 분석

보험은 두 가지로 나눠 봤습니다. has_insurance_selected_event는 화면/이벤트상 선택 행동이고, has_reservation_insurance_row는 실제 예약 DB에 보험 row가 붙었는지입니다. 세그먼트 차이는 이벤트 기준이 더 잘 드러납니다.

6. 가격민감도 분석

예약의 final_price_base 기준으로 전체 하위 25%를 저가, 상위 25%를 고가로 정의했습니다. 고가 결제율 - 저가 결제율이 크게 음수면 가격민감도가 높은 것으로 봤습니다.

Column Guide

  • segment_rate: 해당 세그먼트 안에서의 도달률/선택률/결제율입니다.
  • rest_rate: 해당 세그먼트를 제외한 나머지 전체의 같은 비율입니다.
  • diff_pp: segment_rate - rest_rate입니다. 양수면 세그먼트가 더 높고, 음수면 더 낮습니다.
  • q_value: 여러 세그먼트와 단계를 동시에 비교한 뒤 FDR 보정한 p-value입니다. 0.05 미만이면 유의한 차이로 표시했습니다.
  • meets_min_users, meets_min_reservations: 작은 표본의 과해석을 막기 위한 최소 표본 기준입니다.
